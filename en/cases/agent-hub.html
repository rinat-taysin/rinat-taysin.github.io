An operations team of AI agents that leaves me only the decisions

I run several projects at once: a mobile app I work on under contract, a partner’s B2B platform, and my own AI service. Instead of tracking all of it in my head, I built a system of agents. It listens to my messenger, files incoming requests into trackers, works on tasks in the background, and brings me only the decisions. It’s where I worked out the patterns I now use to automate business operations.

Role
Sole designer and developer
When
Since July 2026, in daily use
Scale
5 always-on agents, 10 scheduled jobs

The business problem

Any team that handles a steady flow of requests has the same problem. Messages arrive in chat apps and as voice notes, tasks live in several trackers, work stalls between people, and the manager is the one who keeps track of what matters most right now. That makes the manager the bottleneck.

I handed that routine to agents: watching trackers and messengers, sorting incoming messages and voice notes, picking what to do next, chasing stalled work, watching logins and outages, backups, and disk cleanup. The goal: I make the top-level calls, and agents do the rest.

What I built

It’s the same pipeline a business runs: messenger intake → tracker → execution → only decisions reach the human. Model-based agents and plain code split the work: anything that can be computed is computed by a script.

  • Operator. Plain code, no model. Listens to the Max messenger, transcribes voice, and routes messages between agents every 15 seconds. At 9 a.m. it sends one “Decisions” batch: questions from agents, each with a recommendation and a default.
  • Hub agent. The central agent, an always-on Claude Code session. It thinks, replies in the messenger, and hands larger jobs to background workers.
  • Desk agents. A “desk” is one area of work, such as a project or my personal errands, and each desk has its own always-on agent. All of them follow a shared contract and talk through the hub using five message types: reply, question, request to another desk, request to the hub, and “needs the owner.” Every restart opens a fresh chat and carries over only open items; all desks restart nightly at 4 a.m.
  • Lanes (background workers). Background Claude sessions, one Linear task each, each in its own git worktree, up to three in parallel. They report back “done” or “failed,” and the hub agent merges.
  • Inbox triage. Takes dictated notes, voice memos from the phone, and the Linear inbox, and files them into trackers without asking me anything.
  • Priority list. One ranked list across all areas, recomputed on every request: quick tasks (under 30 minutes) first, then anything due within 48 hours, then anything with a real consequence, then the rest by priority. If hours pile up in one area while something urgent waits elsewhere, I get a short nudge, no more than twice on a weekday.
  • Stall sweep. A check every 30 minutes plus a daily sweep of all desks. A stalled task goes back to the agent that owns it until it moves, and the check looks at the task itself, not at a status flag. Once a week there’s a retro: 8 subagents review the week from different angles, and a list of proposed fixes comes to me for approval.
  • Watchdog. Every 10 minutes it checks processes, service logins, Docker (restarting it when needed), and disks. One message per failure per day.
  • Nightly jobs. Document backup to the cloud, photo transfer from the phone, cleanup to the Recycle Bin, and a weekly startup-apps checkup. All plain code, no model.
  • Toolkit. 13 shared tools: one MCP gateway to messengers with per-agent chat allowlists, trackers, Figma, a separate browser profile for each agent, and an encrypted key vault. Agents run commands with keys but never see the values.

What it looks like

Principles

  • Code computes, the model judges

    Anything that can be computed without an LLM is done by a script. The model only makes judgment calls, and I pick the lightest one that does the job.

  • The system doesn’t start conversations

    Only a short, closed list: an answer, an outage, a question with a default, a fact summary, a weekly review.

  • Agents carry the backlog, not the human

    Every open task has an owning desk. Unanswered items don’t pile up on the human; an agent keeps pushing them.

  • Keys stay locked

    Agents never see key values. Each desk’s permissions are an allowlist in its config.

  • Every rule lives in one place

    A correction goes straight into code, a test, a hook, or an instruction. Outdated rules get deleted, not stacked next to the new ones.
