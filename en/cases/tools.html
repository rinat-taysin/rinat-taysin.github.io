One toolkit for every agent, each with its own permissions

My agents need chat apps, issue trackers, design files, API keys and a browser. I built all of that once, as a shared set of 13 tools. What a given agent may touch is set in that agent's config, so adding a new project means a few lines of settings, not another copy of the code.

The problem

I run several agent systems: one for a mobile app team, some for partner projects, and a personal hub. They all need the same things: chats, tasks, designs, API keys.

Without a shared kit, every project needs its own copy: its own tracker client, its own messenger bridge, its own place for keys. A bug has to be fixed in every copy, and the only way to tell which agent can see what is to read each one’s code.

I needed one home for the shared code and a clear boundary: a project's agent sees its own chats and tasks and nothing else.

What I built

The core rule: tools don't know who uses them. There are no project names or chat lists in the code. Each agent passes its own config when it connects, and that config lists everything it's allowed to do: which chats to read and where to post, which tracker projects, which design files, which browser profile, which key vault. The permission check lives inside the tool, so it applies the same way from the command line and over MCP.

GroqDictate: dictate into any window

I press a hotkey and talk. The audio goes to Groq for speech recognition, a small language model cleans up false starts, a word list fixes names and terms, and the text is pasted wherever the cursor was. That's how I give tasks to agents and write messages and notes by voice without switching apps. It's a single .NET .exe of about 1.8 MB, no installer.

Key vault: secrets stay locked

API keys and tokens are stored encrypted, one vault per project, with production kept apart from development. The master copy lives in Bitwarden. Agents never see a key: there is no “show value” command. An agent runs a program through the vault, and the keys go only into that program's environment. Nobody copies tokens between projects by hand anymore.

Messaging: one entry point for chat apps

The Max messenger, WhatsApp and Telegram sit behind one MCP server with a local message archive. A project's agent sees only the chats on its allowlist and can post only where it's allowed to. Agents don't need their own messenger sessions, and I don't have to check whether one is reading more than it should.

Trackers: Linear and Jira, scoped per project

One library, CLI and MCP server for everyone. The config says which teams and projects an agent can read and where it can write. Other projects' issues never reach it: the filter goes into the tracker query, and the response is checked again. The tool also watches the per-key rate limit, so several agents can't burn through it together.

Figma: designs without spending API quota

An agent building a screen needs the design, but Figma's official API quota is small. Once a day the tool checks the file version and saves a snapshot to disk, and during the day agents read designs only from that snapshot, as often as they like. Each agent sees only its own files.

The rest is simpler: a separate Chrome profile per agent so they don't grab each other's tabs, a pool of accounts for mobile builds, and the runtime for the always-on agent sessions.
